# PetCare

### Информационная система учёта домашних животных

Модульное веб-приложение для управления карточками питомцев, ведения дневника ухода и контроля доступа пользователей.

**Python 3.11 · FastAPI · PostgreSQL 15 · HTML/CSS/JavaScript · Docker Compose**

## 🐾 О проекте

**PetCare** — учебный проект по дисциплине «Проектирование информационных систем». Система предназначена для хранения информации о домашних животных и ведения истории ухода за ними.

Пользователь может управлять карточками своих питомцев и добавлять записи об уходе. Администратор получает доступ к управлению каталогом и просмотру журнала аудита.

## ✨ Возможности

- **Регистрация и авторизация** — вход в систему с использованием JWT.
- **Карточки питомцев** — создание, просмотр, изменение и удаление собственных записей.
- **Дневник ухода** — записи о кормлении, прогулках, здоровье, вакцинации и заметках.
- **Каталог животных** — просмотр каталога пользователями и управление каталогом администратором.
- **Роли и права доступа** — разделение возможностей клиента и администратора.
- **Журнал аудита** — фиксация важных действий в системе.
- **Поиск и фильтрация** — удобная работа с информацией.
- **Адаптивный интерфейс** — SPA-интерфейс на HTML, CSS и JavaScript, включая тёмную тему.
- **Пользовательские истории** — 60 историй в GitHub Issues, включая 20 историй MVP.

## 🛠 Технологический стек

- **Backend:** Python 3.11, FastAPI, SQLAlchemy, Pydantic
- **Авторизация:** JWT HS256, bcrypt
- **Database:** PostgreSQL 15
- **Frontend:** HTML5, CSS3, JavaScript (SPA)
- **Web server:** Nginx Alpine
- **Инфраструктура:** Docker, Docker Compose

## 🏗 Архитектура

```text
Пользователь
    |
    v
Frontend (HTML / CSS / JavaScript)
    | HTTP-запросы к API, JSON
    v
Backend (Python / FastAPI)
    |-- проверка данных (Pydantic)
    |-- авторизация и проверка ролей (JWT)
    |-- доступ к данным (SQLAlchemy)
    |-- журнал аудита
    v
PostgreSQL 15
```

Frontend отвечает за интерфейс и отправку запросов. Backend обрабатывает запросы, выполняет бизнес-логику и проверяет права доступа. PostgreSQL хранит данные приложения. Nginx раздаёт статические файлы frontend, а Docker Compose запускает сервисы совместно.

## 🚀 Быстрый запуск

### Требования

- Docker Desktop (Windows/macOS) или Docker Engine;
- Docker Compose v2;
- интернет для загрузки образов при первом запуске.

### 1. Клонирование репозитория

```bash
git clone https://github.com/dakakakaA/PetCare.git
cd PetCare
```

### 2. Настройка окружения

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env
```

**Linux/macOS:**

```bash
cp .env.example .env
```

Проверьте настройки в `.env`. Для production обязательно задайте надёжный пароль базы данных и собственный длинный `SECRET_KEY`. Не публикуйте `.env` в GitHub.

### 3. Запуск приложения

В корневой папке проекта выполните:

```bash
docker compose up --build -d
```

### 4. Адреса сервисов

- **Веб-интерфейс (UI):** [http://localhost:3000](http://localhost:3000)
- **Проверка API:** [http://localhost:3000/api/health](http://localhost:3000/api/health)
- **Swagger / OpenAPI:** `/docs` на backend. Если порт backend не опубликован в `docker-compose.yml`, документация доступна только из контейнерной сети; для доступа с компьютера потребуется соответствующая публикация порта.

### Остановка

```bash
docker compose down
```

> `docker compose down -v` удаляет также связанные Docker volumes и может удалить данные базы. Используйте эту команду только если действительно хотите удалить данные.

## 👤 Тестовые учётные записи

В проекте предусмотрены демонстрационные учётные записи:

| Роль | Логин | Пароль | Назначение |
|---|---|---|---|
| Клиент (`Client`) | `client` | `client123` | Работа со своими питомцами и дневником ухода |
| Администратор (`Admin`) | `admin` | `admin123` | Административные функции и журнал аудита |

Используйте эти учётные записи только для локальной демонстрации. Не применяйте демонстрационные пароли в production.

## 🔐 Безопасность

- JWT используется для авторизации защищённых запросов.
- Пароли хранятся в виде bcrypt-хешей.
- Backend проверяет роль пользователя при доступе к административным операциям.
- Операции с питомцами и записями ухода ограничиваются правами владельца.
- `.env` исключён из Git через `.gitignore`; в репозитории хранится пример `.env.example`.
